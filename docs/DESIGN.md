# LuckyNote 暖窝账本 — 完整产品与技术方案

面向 NAS Docker 自托管的家庭记账系统：多人独立记账、家庭总览、副业经营账本，以及通过 OpenClaw + 微信语音自动入账。

---

## 1. 产品定位

| 维度 | 选择 |
| --- | --- |
| 场景 | 家庭 NAS 私有部署，数据不出内网 |
| 对标 | 钱迹（极简记账）、随手记（家庭/生意多账本）、鲨鱼记账（语音）、OtterFin / ezBookkeeping（自托管） |
| 差异 | 经营账本与生活账本隔离；为 OpenClaw 预留结构化入账 API；温馨卡通 UI |
| 部署 | 单容器 + 数据卷，`docker compose up -d` |

产品名 **LuckyNote（暖窝账本）**：窝 = 家庭，暖 = 视觉与语气，Note = 随手记一笔。

---

## 2. 市面与开源对照（功能取舍）

### 2.1 商业产品

| 能力 | 钱迹 | 随手记 | 鲨鱼/记账吧 | LuckyNote |
| --- | --- | --- | --- | --- |
| 收支 / 转账 | ✓ | ✓ | ✓ | ✓ |
| 多账户（现金/卡/钱包） | ✓ | ✓ | ✓ | ✓ |
| 一二级分类 | ✓ | ✓ | ✓ | ✓（一级 + 图标） |
| 预算 | ✓ | ✓ | ✓ | ✓（月度总预算 + 分类） |
| 报表（饼/趋势） | ✓ | ✓ | ✓ | ✓ |
| 多账本 | 有限 | 家庭/生意模板 | 共享账本 | 个人 / 家庭 / 经营 三本 |
| 多人协同 | 部分 | 家庭账 | 强 | 家庭成员 + 角色 |
| 语音/AI | 弱 | 票据识别 | 聊天记账 | OpenClaw 微信语音 |
| 自托管 | ✗ | ✗ | ✗ | ✓ Docker |

### 2.2 开源参考

- **ezBookkeeping**：轻量、NAS 友好、单命令 Docker — 部署形态对齐。
- **Firefly III**：复式记账、预算规则完整 — 本项目采用**单式记账**（金额为正 + 收支类型），降低家庭用户门槛。
- **OtterFin / ShreeOne**：Household 为顶层实体、角色权限 — 数据模型对齐。
- **OpenClaw 记账 Skill 实践**：微信自然语言 → 解析 → 写入表格；本项目把「表格」换成自家 API。

不纳入首期：银行同步、投资行情、社区、广告、多币种、信用卡账单日引擎（可后续加）。

## 3. 核心用户故事

1. **家长**登录后看到本月家庭总收入、总支出、结余，以及每位成员的花费占比。
2. **伴侣**只给自己记「午餐 32」，该笔记入个人账本，同时进入家庭总览。
3. **副业**：一笔「接了海报设计收了 800」记入**经营账本**，默认**不混入**日常家庭餐饮统计，但在经营页看进账、成本和毛利。
4. **微信**：对 OpenClaw 说「昨天买菜花了 86，记到家庭账」，语音转文字后自动入账，并回复确认卡片。
5. **预算**：餐饮月预算 2500，超 80% 在仪表盘变暖橙提示。

## 4. 信息架构

```
家庭 Household
 ├─ 成员 User（家长 owner / 成员 member / 只读 viewer）
 ├─ 账本 Ledger
 │    ├─ 个人账本（每人一本，owner_user_id）
 │    ├─ 家庭公共账本（水电、房租、共同采购）
 │    └─ 经营账本（可多人共用，type=business）
 ├─ 资金账户 Account（现金、银行卡、微信、支付宝、经营收款）
 ├─ 分类 Category（按账本类型隔离：生活 vs 经营）
 ├─ 流水 Transaction
 └─ 预算 Budget
```

### 4.1 三本账如何汇总

| 账本 | 记什么 | 计入「家庭收支总览」 | 计入「经营损益」 |
| --- | --- | --- | --- |
| 个人 | 各自日常消费、工资等 | 是（可按成员拆开） | 否 |
| 家庭 | 公共开支、家庭收入 | 是 | 否 |
| 经营 | 副业收入、进货、平台扣点 | **否**（避免稀释生活消费结构） | 是 |

家庭总览仍可展示一行「本月经营净利」，作为财富补充，但不进入餐饮/交通饼图。

### 4.2 权限

| 动作 | owner | member | viewer |
| --- | --- | --- | --- |
| 记自己的个人账 | ✓ | ✓ | ✗ |
| 记家庭公共账 | ✓ | ✓ | ✗ |
| 记经营账 | ✓ | ✓（默认可写） | ✗ |
| 看他人个人明细 | ✓ | ✗（只看汇总） | 只看汇总 |
| 邀请成员 / 重置 Token | ✓ | ✗ | ✗ |

微信绑定：成员资料里填写 `wechat_alias`（微信备注名或昵称），OpenClaw 入账时按别名落到对应人。

## 5. 功能清单（分期）

### 一期（本仓库已实现）

- 登录、家庭成员、三账本切换
- 快速记账、流水筛选、编辑删除
- 仪表盘：本月收支、结余、成员对比、分类饼图、近 6 月趋势
- 经营页：收入 / 成本 / 毛利
- 月度预算与进度
- 分类与资金账户管理
- AI 入账：自然语言解析 + 结构化 API + 审计日志
- OpenClaw Skill（微信语音/文字）
- Docker Compose、数据卷持久化、演示数据
- 手机底部导航 + PWA 添加到主屏幕

### 二期

- 周期记账（房租、订阅）
- 转账 / 还款、债权债务
- 账单图片附件、CSV 导入（支付宝/微信导出）
- 二级分类、标签、日历视图
- 反向确认：不确定金额时微信先问一句再落账

### 三期

- 多经营主体（不止一个副业）
- 发票/进项简易台账
- 本地大模型二次分类（NAS Ollama）
- HTTPS 反代模板（Caddy / 群晖反代）

## 6. 技术架构

```
                    ┌─────────────────┐
  手机浏览器 / 平板  │  LuckyNote Web  │
                    └────────┬────────┘
                             │ HTTPS(内网)
                    ┌────────▼────────┐
                    │  FastAPI + 静态  │  Docker
                    │  SQLite (WAL)    │
                    └────────▲────────┘
                             │ Token  API
          ┌──────────────────┴──────────────────┐
          │         NAS 上的 OpenClaw            │
          │  微信通道 → ASR → Skill → HTTP POST  │
          └─────────────────────────────────────┘
```

**为何单容器 + SQLite**

- 群晖 / 绿联 / 威联通：少编排、少内存。
- 家庭并发极低，WAL 模式足够。
- 数据只有一个 `data/luckynote.db` 卷，备份即拷贝。

**技术栈**

| 层 | 选型 |
| --- | --- |
| API | Python 3.12、FastAPI、SQLAlchemy 2 |
| 鉴权 | JWT（Web）+ 长期 API Token（OpenClaw） |
| 前端 | React 18、Vite、手写温馨主题 CSS |
| 图表 | Recharts |
| 解析 | 规则引擎（中文数字、多笔、账本意图） |

OpenClaw 已完成语音转写时，Skill 把**文本或结构化 JSON**发给 LuckyNote，应用内不必再跑大模型。未结构化时走本地规则解析。

## 7. AI / 微信自动记账协议

### 7.1 链路

1. 用户对「微信 ClawBot」发语音：「中午吃饭 35，记我账上」。
2. OpenClaw 音频节点转写为文字。
3. Skill 判断为记账意图，调用 `POST /api/v1/ai/ingest`。
4. 服务端：匹配成员 → 解析金额/分类/账本 → 写入流水 → 返回确认文案。
5. OpenClaw 把确认发回微信。

### 7.2 鉴权

家长在「设置 → OpenClaw」生成 Token。Skill 环境变量：

- `LUCKYNOTE_BASE_URL` 例如 `http://172.17.0.1:8907`（NAS 上容器互访）
- `LUCKYNOTE_API_TOKEN`

### 7.3 自然语言约定（示例）

| 说法 | 结果 |
| --- | --- |
| 午餐 35 | 个人账本 / 支出 / 餐饮 / 35 |
| 记到家庭：水电 220 | 家庭账本 / 支出 / 居住 |
| 副业收了客户尾款 2000 | 经营账本 / 收入 / 项目款 |
| 进货花了 480 | 经营账本 / 支出 / 进货成本 |
| 工资 12000 | 个人或家庭收入 / 工资 |

多笔：`咖啡 18，地铁 4` → 两条流水。

## 8. UI 设计语言

- **气质**：纸感暖色、圆角卡片、轻阴影；高级感来自留白与字体，而不是深色极客风。
- **色板**：奶油底 `#FBF6F0`、墨色字 `#3D405B`、珊瑚行动色 `#E07A5F`、鼠尾草绿 `#81B29A`、黄油点缀 `#F2CC8F`。
- **吉祥物**：圆滚滚的「窝窝」小狐狸，守着一个小房子存钱罐。
- **动效**：按钮轻按、卡片入场；避免夸张粒子。
- **布局**：桌面左侧导航 + 主卡片；手机底部 Tab（总览 / 账本 / 记账 / 经营 / 更多），可添加到主屏幕当轻量 App 用。

## 9. NAS Docker 部署要点

1. 映射 `8907:8907`，数据卷 `./data:/data`。
2. 与 OpenClaw 同一 Docker 网络，或用 NAS 网关 IP 互访。
3. 勿把 8907 直接暴露公网；需要时走 Tailscale / 反向代理 + 强密码。
4. 定期复制 `luckynote.db` 到另一块盘。

---

## 10. 安全

- 密码使用 PBKDF2 哈希。
- OpenClaw Token 只显示一次，库内存哈希。
- AI 入账写审计：原文、解析结果、操作者。
- 默认不向公网提供注册；成员由家长在设置中添加（一期演示账号由种子数据创建）。
